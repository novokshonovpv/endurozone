# Enduro.Zone — требования к каталогу первого поставщика

Дата: 10.10.2026. Статус: требования для переговоров, поставщик ещё не выбран. Импорт и торговля не реализованы. Текущие девять товаров сайта — демонстрационные.

## Что попросить у поставщика сначала

Нужны пример выгрузки товаров, отдельная таблица совместимости, описание полей и способ обновления. Для проверки достаточно 20–50 реальных товарных вариантов и 5–10 точно определённых версий мотоциклов. Включить несколько товаров без подтверждённой совместимости, отсутствующие на складе позиции и исключения по годам. Это предлагаемый объём первой проверки, а не обязательный объём полного каталога.

Подойдут CSV в UTF-8 или JSON; XLSX можно согласовать как исходный формат. В первой интеграции предпочтительна полная выгрузка. API и изменения отдельных строк добавлять после согласования удаления, версий и повторной доставки. Поставщик не должен передавать данные покупателей, пароли или ключи вместе с каталогом.

## Товары: одна строка на продаваемый вариант

| Поле | Требование |
| --- | --- |
| supplier_product_id | Обязательный постоянный ID варианта у поставщика; хранить как строку, сохранять ведущие нули. Ключ обновления: поставщик + этот ID |
| supplier_sku | Артикул поставщика; не заменяет ID без гарантии уникальности и неизменности |
| brand, manufacturer_part_number | Производитель и его артикул, если существуют; не смешивать с артикулом поставщика |
| title, category | Название и категория: запчасти, экипировка, мотоциклы; подкатегория отдельным полем |
| description, attributes | Описание и характеристики с единицами измерения; размер/цвет/исполнение обязательны, если различают варианты |
| price, currency | Цена для покупателя, валюта, условие включения налогов; фиксированная десятичная точность, отрицательные значения запрещены |
| availability | in_stock / out_of_stock / preorder / unknown. Неизвестный остаток нельзя показывать как наличие |
| stock_quantity, stock_unit | Количество и единица, если поставщик их отдаёт. Отдельно срок поставки для предзаказа; пустое значение не равно нулю |
| is_active | Продаётся ли вариант; снятие с продажи не должно удалять историю будущих заказов |
| source_updated_at | Время актуальности данных с часовым поясом. Время получения и успешного импорта площадка записывает отдельно |
| image_urls, product_url | Ссылки на фото и исходную карточку; требуется разрешение на использование изображений и описаний |

Для экипировки нужна сетка размеров производителя и варианты размеров/цветов; подбор по модели мотоцикла обычно не применим. Для продажи мотоциклов нужны год, исполнение, состояние и место наличия; персональные документы и сведения владельцев в общий каталог не включать. Специфические поля этих категорий согласовать отдельным расширением.

## Совместимость: отдельная таблица

Одна строка описывает применимость одного товара к одной версии техники. Название «KTM 250» или текст «подходит ко всем эндуро» не является достаточным основанием для автоматического подбора.

| Поле | Требование |
| --- | --- |
| supplier_product_id | Связь с существующим вариантом товара |
| fitment_id | Постоянный ID записи совместимости, если доступен |
| motorcycle_brand, model | Точное название марки и модели, код производителя при наличии |
| year_from, year_to | Модельные годы включительно; пустое значение означает неизвестность, не все годы |
| engine_code, displacement_cc, engine_cycle | Код/объём/2T или 4T, когда определяют применимость |
| trim, market | Исполнение и рынок поставки, когда определяют применимость |
| fitment_status | confirmed / excluded / unknown |
| source_reference, source_revision | Каталог производителя или документ поставщика, его версия/дата и ссылка либо идентификатор |
| verified_by, verified_at | Кто подтвердил применимость и когда; организация/роль, личные контакты не обязательны |
| restrictions | Исключения, необходимые переходники, ограничения установки; структурированные признаки дополняют текст |

Внутренний справочник техники Enduro.Zone сопоставляется с данными поставщика через отдельную таблицу. Свободное название мотоцикла в гараже не становится автоматически записью справочника. Неоднозначное сопоставление отправляется на ручную проверку.

Статус «подходит» допускается только после сопоставления точной версии техники, подтверждённого источника и проверки исключений. Отсутствие нужного года/исполнения/источника даёт «совместимость не подтверждена». Противоречивые источники блокируют автоматическое подтверждение до разбора. Артикул-заменитель и похожее название сами по себе не доказывают совместимость. Для универсальных деталей нужны проверяемые размеры/крепления; слово «универсальный» не означает гарантированную установку.

## Обновление и обработка ошибок

Согласовать периодичность выгрузки и допустимый срок свежести цен/остатков. Начальный ориентир для обсуждения — раз в сутки, но окончательный срок зависит от поставщика. Просроченные данные помечать; перед будущим оформлением заказа цена и наличие должны перепроверяться. Сейчас оформление заказа отсутствует.

Импорт сначала проходит проверку без публикации: номер партии, дата выгрузки, контрольная сумма, количество строк, ошибки по строкам и предварительные добавления/обновления/снятия. Партию с ошибками не публиковать до исправления в первой версии. Повтор той же партии не создаёт дубликаты. Неудачная загрузка оставляет предыдущую успешную версию. Повторная более старая выгрузка не откатывает новые данные.

Исчезновение строки из файла не означает удаление товара, пока поставщик не подтвердил, что файл полный и отсутствие означает снятие с продажи. Пустые поля, дубли ID, неизвестные валюты, некорректные даты и ссылки на отсутствующие товары должны давать понятные ошибки. HTML очищать; загрузку внешних фото ограничивать размером/типом и разрешёнными адресами, исключая локальные и служебные сети. Ключи API хранить только в серверном окружении.

## Критерии приёмки первой интеграции

- Поля и права использования согласованы, есть реальный образец и ответственный у поставщика.
- Повторный импорт не создаёт дубликаты; обновление цены/остатка и снятие варианта видны в отчёте.
- Невалидная или более старая партия не портит опубликованные данные; доступен возврат к предыдущей версии.
- Проверены подходящая версия техники, исключённый год, неизвестное исполнение, конфликт источников и товар без данных совместимости.
- Подбор в гараже показывает причину, источник и дату подтверждения; неизвестность не превращается в «подходит».
- Демонстрационные позиции отделены от реальных. Нет кнопки оплаты до реализации и приёмки заказа.

## Вопросы для первого разговора

1. Как получить разрешённую выгрузку и кто отвечает за её качество?
2. Какие поля, постоянные ID, цены/валюты и данные наличия доступны?
3. Есть ли каталог применимости производителя, исключения и право показывать источник?
4. Как часто обновляются данные и что означает исчезновение товара из файла?
5. Можно ли использовать описания и фотографии на сайте и в будущих приложениях?
6. Как поставщик подтверждает цену/остаток перед будущим заказом, обрабатывает поставку и возврат?

Следующая задача разработки после получения образца: адаптер этого поставщика, проверка без публикации и отчёт ошибок. До образца не закреплять его формат и не выдавать демонстрационный подбор за реальную применимость.
