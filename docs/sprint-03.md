# Спринт 03: GPX и совместные покатушки

Версия 0.5.0 реализует сценарий: загрузка GPX → предпросмотр → модерация → публикация → покатушка → заявка → подтверждение участия.

## Приёмка вдвоём

1. Запустить проект по README и создать два тестовых аккаунта. Использовать искусственный GPX и явно обозначить тест без реального выезда.
2. Первый аккаунт загружает GPX, выбирает радиус скрытия и осматривает публичную геометрию. Предпросмотр не сохраняется в базе.
3. После отправки автор видит ожидающий трек; второй аккаунт и гость не видят его даже по прямой ссылке. Оригинал скачивается только автором.
4. Оператор назначает тестовому модератору роль по [инструкции](runbooks/moderation.md). Модератор проверяет очищенную геометрию и условия доступа, публикует с причиной. Оригинал ему недоступен.
5. Второй аккаунт создаёт покатушку на опубликованном треке: будущая дата, часовой пояс, лимит и приватные сведения о сборе.
6. Первый аккаунт подаёт заявку. До подтверждения сведения о сборе скрыты. Организатор принимает заявку: участнику открываются сведения, счётчик учитывает организатора.
7. Проверить выход, отказ, отмену и скрытие трека по жалобе. Отмена и скрытие закрывают доступ участников к сбору; скрытый трек убирает покатушку из публичного списка.
8. Снять временную роль модератора. После перезапуска проверить сохранение данных.

## Разделение работы

Бэкенд и мобильные приложения: проверить API, миграцию 003 и обычный PostgreSQL. Продукт и интерфейс: пройти приёмку, определить правила публикации, обработки заявок и модерации событий. Замечания фиксировать в GitHub с шагами воспроизведения и ожидаемым результатом.

## Следующий этап

Перед реальным пилотом нужны подтверждение email и восстановление доступа, уведомления, модерация событий, удаление данных и защищённое хранение оригиналов и резервных копий. Поиск по радиусу и PostGIS, чат, редактирование событий и версии треков пока отсутствуют. Магазин, обучение, ИИ-механик и приложения остаются отдельными следующими этапами.
