# Спринт 11 — фотографии · 0.13

## Результат

Одна обложка мотоцикла и до шести изображений в записи. Управление доступно владельцу в гараже или на странице сохранённой записи; гости видят только публичные фото. Увеличенный просмотр доступен из записи, ленты и публичного гаража. Добавление фото при создании записи выполняется следующим шагом после её сохранения.

## Приёмка двумя основателями

1. На тестовом аккаунте добавьте синтетический JPEG/PNG/WebP в гараже. Обновите страницу: обложка сохранилась. Откройте увеличенный просмотр, закройте его.
2. Сохраните тестовую запись, добавьте несколько фотографий на её странице. Проверьте ленту и публичную страницу райдера с другого аккаунта и без входа.
3. Сделайте запись закрытой: её фото и прямые ссылки должны возвращать 404 для другого участника и гостя. Владелец продолжает видеть их. Если у мотоцикла не осталось открытых нескрытых записей, его обложка также становится приватной.
4. Проверьте SVG, повреждённый файл, анимацию, превышение 5 МБ, седьмое изображение в записи. Ожидается понятная ошибка без изменения сохранённых фото.
5. На собственных тестовых изображениях проверьте замену обложки и подтверждённое удаление фото. Замена необратимо удаляет старую обложку. При отказе загрузки по квоте старая обложка сохраняется.
6. Проверьте интерфейс на узком экране, сообщения об ошибке и повтор загрузки. В выгрузке своего аккаунта присутствуют собственные обработанные JPEG; чужих файлов нет.

Для проверки используйте тестовые данные. Старые страницы и уже полученные файлы посетителя технически нельзя отозвать; новые запросы проверяют текущую видимость.

## API и ограничения

| Адрес                        | Действие                              |
| ---------------------------- | ------------------------------------- |
| GET `/api/bikes/:id/photos`  | Обложка доступного мотоцикла          |
| POST `/api/bikes/:id/photos` | Добавить/заменить собственную обложку |
| GET `/api/posts/:id/photos`  | Изображения доступной записи          |
| POST `/api/posts/:id/photos` | Добавить фото в собственную запись    |
| GET `/api/photos/:id/image`  | JPEG с проверкой текущего доступа     |
| DELETE `/api/photos/:id`     | Удалить собственное фото              |

Загрузка: JSON `{data: base64}` без префикса data URL. CSRF, сессия, доверенный источник и подтверждённый email в режиме пилота обязательны для изменений. Ответ содержит только id, URL, размер изображения и время загрузки. Имя файла и исходный файл не сохраняются. Форматы определяются по сигнатуре и декодеру, а не расширению.

Вход: 5 МБ, 24 миллиона пикселей, JPEG/PNG/WebP без анимации. Выход: JPEG, качество 82, до 1600 пикселей по каждой стороне, не более 2 МБ. Прозрачность сводится на белый фон. Удаляется EXIF, включая GPS, ICC/XMP и прочие исходные метаданные. Обработка использует sharp; [описание параметров](https://sharp.pixelplumbing.com/api-constructor/), [параметры вывода](https://sharp.pixelplumbing.com/api-output/).

Один процесс одновременно декодирует максимум два изображения; превышение даёт 429. Загрузка ограничена 20 запросами в минуту на адрес клиента для каждого маршрута. Сохранение блокирует строку аккаунта и целевого объекта: параллельные запросы не превышают лимит шести фото, 100 фото/50 МБ на аккаунт. При замене и превышении квоты транзакция откатывается вместе с удалением старой обложки.

Миграция 009 хранит обработанные файлы в bytea. Удаление объектов каскадно удаляет изображения; не остаётся внешних файлов-сирот. GET не использует публичный файловый сервер или CDN, имеет `no-store` и `nosniff`. У владельца нет расширения публичных DTO: права проверяются отдельными маршрутами.

Экспорт содержит `photos` с `jpeg_base64`; исходники недоступны, поскольку не сохраняются. При суммарном размере JPEG более 18 МБ или итоговом JSON более 25 МБ нужен оператор для полной выгрузки. Бэкапы и внешние копии не удаляются интерфейсом.

## Проверки и дальнейшая очередь

Автоматические проверки: декодирование и метаданные, поворот, уменьшение, форматы и лимиты, видимость при закрытии/модерации, CSRF и чужое владение, обязательный email, квоты, параллельное последнее место, приватный экспорт и каскадное удаление. Общие проверки выполняются на PGlite и в CI на PostgreSQL.

Следующий этап — подписки на райдеров, избранные записи и лента подписок. Далее — геопозиция и поиск трасс/покатушек по расстоянию. Общий HTTPS-стенд остаётся отложенным решением пользователя. Объектное хранилище/очередь обработки, отдельная модерация изображений, фото в вопросах механику, редактирование/порядок/подписи и загрузка пачкой не входят в эту версию.
