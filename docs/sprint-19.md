# Спринт 19 — подбор запчастей по узлам · 0.22

## Результат

- Раздел **«Запчасти»** (`#parts`) вместо «Магазина» в меню: «Мои мотоциклы» (привязанные к модели) и выбор марки → модели.
- **Модель** (`#parts/<slug>`): вкладки **«Мотоцикл»** (14 узлов) и **«Двигатель <код>»** (11 узлов) — плитки со схемами Enduro.Zone.
- **Узел** (`#parts/<slug>/<moto|engine>/<узел>`): крупная схема, **паспорт** (размеры и коды из характеристик с кнопкой «Копировать»), **таблица деталей** (появится после подключения каталога поставщика), **«Что подошло владельцам»** — запись с артикулом и комментарием, «Подошло и мне».
- В гараже кнопка **«Подобрать запчасти»** ведёт на модель своего мотоцикла; в карточке модели — кнопка «Подбор запчастей». На телефоне раздел живёт внутри «Гаража».

## Решения

Пользователь 13.10.2026: магазин скрыть до наполнения сообщества; подбор запчастей — ключевая функция, ориентир — подбор Velocity (марка → модель → мотоцикл / двигатель → узлы); схемы рисовать свои; данные поставщика — позже, сначала каркас. Детали по умолчанию:

- **Магазин скрыт** из меню; адрес `#shop` пока открывается, код не удалён.
- **Схемы узлов** — собственные условные рисунки (`apps/web/src/node-art.tsx`), без чужих изображений.
- **Двигатель общий для моделей** с одинаковым кодом (TYX300, 172FMM-3A, NB300…): код берётся из строк «Модель двигателя / Маркировка / Двигатель» (у 600+ из 863 моделей), префикс ZS отбрасывается. Опыт владельцев по узлам двигателя виден на всех таких моделях.
- **Паспорт** собирается из характеристик правилами по названиям строк: шины, цепь, звёзды, тормоза, вилка, амортизатор, аккумулятор, бак; у двигателя — код, свеча, масло, охлаждение, сцепление, КПП, питание. Шум («колёсная база», «прозрачный бак») отсеивается.
- **Добавлять и подтверждать** могут только владельцы: мотоцикл в гараже привязан к этой модели (для двигателя — к любой модели с этим двигателем). Свою запись подтверждать нельзя. Без ссылок (400 `LINKS_NOT_ALLOWED`), не больше 50 записей автора на модель/двигатель. Удаляет автор или модератор (с записью в журнале). Записи людей в блокировке с читателем скрыты. Записи и отметки входят в выгрузку данных и удаляются вместе с аккаунтом.
- **Таблицы деталей поставщика** — `node scripts/import-parts.mjs <папка с CSV> [out.json]` → `apps/api/data/parts.json`; формат — [docs/parts-template.csv](parts-template.csv) (scope, key, node, position, name, article, qty, note). Загружать только данные, на которые есть право (разрешение Velocity или своё). Пока файла нет — таблицы пустые.

## Официальные схемы KAYO · 0.22.1

Пользователь 13.10.2026 предложил интегрировать каталог https://kayo.ru/schemes/ (67 схем, у модели ~20 узлов со схемами). На сайте KAYO: «Использование информации возможно только с письменного согласия владельцев сайта» — поэтому схемы и таблицы не переносятся. Сделано без копирования: у 25 моделей KAYO справочника, название которых **точно** совпадает со схемой на kayo.ru (без учёта года и слова «кроссовый»), на странице модели и в узлах — карточка «Официальная схема запчастей KAYO ↗», открывающая страницу производителя. Хранятся только адрес и заголовок схемы (`apps/api/data/external-schemes.json`, обновление — `node scripts/import-kayo-schemes.mjs`). Новые модели 2026 года и похожие, но не совпадающие названия (LUX и т. п.) ссылку не получают, чтобы не вести на чужую схему. Для переноса таблиц в узлы нужно письменное согласие KAYO; после него — импорт CSV.

## Состав узлов KAYO · 0.23

Пользователь 13–14.10.2026: 67МОТО — дилер KAYO и вправе использовать эти данные; загрузить состав узлов для проверки структуры, без изображений и артикулов. Сделано `scripts/import-kayo-parts.mts`: для 25 моделей со ссылкой на kayo.ru взяты номер на схеме, название детали (применимость KAYO — в примечании) и количество в узле; артикулы, цены, наличие и картинки не берутся. Итог: **5087 строк**, источник «KAYO» в таблице узла и ссылка на схему производителя. Запросы шли по одному с паузой; повторный проход с расширенным сопоставлением не завершён — kayo.ru перестал отвечать с компьютера разработки, повторять позже.

Что показали данные о нашей структуре узлов:
- **Мотоцикл ложится хорошо**: узлы KAYO «Руль», «Тормоза», «Траверсы», «Колёса», «Рама», «Маятник», «Подвеска», «Подножки», «Глушитель», «Электрика», «Фара», «Пластик», «Наклейки» однозначно раскладываются по нашим 14.
- **Названия у KAYO не единые**: у старых схем те же узлы зовутся иначе («Колесо переднее» / «Переднее колесо», «Траверса», «Амортизаторы передние», «Тормоз задний»…) — нужен словарь синонимов на бренд (добавлен в импорт, применится при следующем проходе).
- **Двигатель у KAYO — один общий узел** с немногими позициями, а не 11 подузлов: детали раскладываются по нашим узлам двигателя по названию; «Воздушный фильтр», «Карбюратор», «Система охлаждения» — отдельные узлы KAYO, относим к двигателю. У 6 моделей без кода двигателя в характеристиках детали двигателя пока не показываются.
- Вывод: оставить 14 + 11 узлов, для каждого бренда держать словарь сопоставления; «Воздушный фильтр» имеет смысл вынести в отдельный узел мотоцикла, если так же устроят другие бренды.

## API

| Адрес | Действие |
| --- | --- |
| GET `/api/parts/:slug` | Модель, двигатель (код, сколько ещё моделей), узлы мотоцикла и двигателя с числом размеров, деталей и записей |
| GET `/api/parts/:slug/:scope/:node` | Узел: паспорт, детали, записи владельцев, `viewerOwns` |
| POST `/api/parts/:slug/:scope/:node/fits` | `{name, partNumber, comment}` — только владельцы; 403 `OWNER_REQUIRED`, 400 `LINKS_NOT_ALLOWED`, 409 `FIT_LIMIT` |
| DELETE `/api/part-fits/:id` | Автор или модератор |
| PUT / DELETE `/api/part-fits/:id/vote` | «Подошло и мне» — владельцы, не автор |

## Данные

Миграция 017: `part_fits`, `part_fit_votes`. Версия 0.22.0.
