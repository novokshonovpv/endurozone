# Проверка прав и безопасности · 16.10.2026 (0.29.3)

Проверены все 133 операции API (список — из OpenAPI), публичные страницы превью и загрузки файлов. Цель — перед приглашением первых райдеров убедиться, что личное не утекает, а чужое нельзя изменить.

## Что проверено и в порядке

- **Доступ по ролям — автоматически.** Новый тест `apps/api/test/access-matrix.test.ts` проходит по всем операциям из OpenAPI: ни одна операция модератора не выполняется для райдера и гостя (чтение — строго 403), ни одна операция для вошедших не выполняется для гостя (чтение — строго 401). Тест ловит будущие маршруты без защиты.
- **Чужие объекты по id.** Мотоциклы и планы ТО (план ищется только через свой мотоцикл), записи и комментарии, фото, треки (исходный GPX — только автору), покатушки (точка сбора — организатору и принятым участникам до старта; список участников и решения по заявкам — только организатору), чат (организатор и принятые; модератор видит только сообщение с жалобой), записи о запчастях, консультации механика, уведомления, отметки «Был здесь».
- **Фото.** Изображение из закрытой записи отдаётся только автору; файлы перекодируются в JPEG (метаданные и геометка удаляются), лимиты размера, количества и мегапикселей.
- **Утечки полей.** Ответы собираются явными функциями и проходят через схемы ответа (лишние поля отрезаются); email, хэш пароля, исходный GPX, точка сбора в публичные ответы не попадают. Страницы превью `/s/…` описывают только видимое гостю и экранируют текст.
- **SQL.** Все значения от пользователя передаются параметрами; в текст запросов подставляются только номера параметров.
- **Вход и восстановление.** Пароли — scrypt; сессия — cookie `httpOnly`, `sameSite=lax`, на стенде `secure`; CSRF-токен и проверка источника для всех изменений; вход, регистрация и письма — до 10 попыток в минуту с адреса; ответ на запрос сброса одинаков для существующих и несуществующих адресов; коды хранятся в виде хэшей, одноразовые, сброс пароля завершает все сессии. Служебный аккаунт стартового наполнения войти не может.
- **GPX.** Запрещены DTD и сущности (защита от XML-атак), ограничены размер и сложность файла.
- **Ошибки.** Внутренние ошибки показываются пользователю общей фразой, подробности — только в журнале сервера.
- **Веб-страница.** Нет вставки сырого HTML; ссылки на источники анонсов принимаются только `https://`.

## Исправлено в этой проверке

- Добавлены заголовки безопасности: запрет встраивать сайт в чужие страницы (`X-Frame-Options: SAMEORIGIN`, `frame-ancestors 'self'` — защита от «кликджекинга»), геопозиция только для своих страниц, камера и микрофон запрещены (`Permissions-Policy`), за HTTPS браузер полгода ходит только по HTTPS (`Strict-Transport-Security`).

## Рекомендации (не исправлялись — требуют решения)

1. **Подтверждение email на стенде выключено** (`REQUIRE_VERIFIED_EMAIL=false`), а стенд открыт без пароля: зарегистрироваться и писать может кто угодно с любым адресом. Пока письма стенда не уходят наружу, включать нельзя — сначала нужна настоящая почта (SMTP), затем включить проверку. До этого спам и нарушения закрываются модерацией и жалобами.
2. Блокировка не скрывает от заблокированного **фото по прямой ссылке** и **записи о запчастях**; это публичные данные, видимые и гостю, поэтому риск низкий.
3. Ограничение попыток входа считается по адресу, а не по аккаунту: подбор пароля к одному аккаунту с многих адресов не ограничен. Для пилота достаточно длинных паролей (от 12 символов); к продакшену — блокировка аккаунта после серии неудач.
4. Резервная копия базы хранится только у провайдера; независимая копия — отдельная задача.
