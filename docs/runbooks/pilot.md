# Почта, доступ и уведомления

## Локальная приёмка

По умолчанию `MAIL_MODE=file`. После регистрации или запроса письма сервер обрабатывает очередь раз в три секунды и сохраняет текст в `.data/mail/<uuid>.txt`. Файл содержит адрес получателя и одноразовую ссылку. Открывать его только на компьютере разработчика; не помещать в Git, публичный архив, чат или журнал ошибок. Почтового ящика через HTTP нет. В production этот режим запрещён. Локальные письма после проверки удалить; они не удаляются автоматически.

Подтверждение: регистрация → письмо → ссылка → явная кнопка подтверждения → «Доступ к аккаунту» → «Проверить подтверждение». Существующие аккаунты мигрируют без подтверждения; запросить письмо в разделе доступа. До подтверждения можно войти и запросить письмо. `REQUIRE_VERIFIED_EMAIL=true` блокирует изменение основных данных, включая публикации, гараж и заявки; операции доступа и отметки уведомлений остаются доступны. В разработке флаг по умолчанию выключен, в production обязателен.

Восстановление: «Забыли пароль?» → адрес → письмо → новый пароль и повтор → вход заново. Ссылка действует 30 минут. Все прежние сеансы отзываются, автоматического входа нет. Подтверждение email действует 24 часа и не создаёт сеанс. Простое открытие любой ссылки не расходует её. Токен передаётся через URL-фрагмент, после успеха убирается из адреса. Не пересылать ссылки, не сохранять их в аналитике и снимках экрана.

## Очередь и SMTP

`account_tokens` хранит только SHA-256 случайного токена. `mail_outbox` до обработки содержит исходную ссылку: база и её резервные копии требуют приватного доступа. После доставки, замены, использования или истечения срока тело очищается; при работающем обработчике просроченные токены удаляются. После пяти неудач тело тоже очищается. История адресата и попыток остаётся; сроки удаления этой истории нужно определить до пилота.

Повторная выдача: не чаще одного письма каждого назначения в минуту и максимум пять в час на аккаунт; также действует лимит запросов по IP. Повторный запрос в период ожидания отвечает одинаково, без новой ссылки. Новая выдача отзывает прежний токен и закрывает ещё не доставленное старое письмо. Известный и неизвестный адрес при восстановлении получают одинаковый ответ; отсутствие аккаунта не создаёт письмо.

Заполнить закрытый `.env`: `MAIL_MODE=smtp`, `SMTP_HOST`, `SMTP_PORT`, `SMTP_SECURE`, `SMTP_USER`, `SMTP_PASSWORD`, `MAIL_FROM`. Порт 465 использует TLS сразу; для 587 выбрать `SMTP_SECURE=false`, STARTTLS всё равно обязателен. Проверка сертификата не отключается. Использовать собственный подтверждённый домен отправителя, настроить SPF/DKIM/DMARC у провайдера и проверить доставку на тестовые адреса. SMTP с реальным провайдером в этой версии не проверен и не подключён.

Ошибки доставки оставляют письмо на повтор через пять минут, до пяти попыток и до срока действия ссылки. Проверять `mail_outbox.attempts`, `sent_at`, `next_attempt_at` без вывода `body`. `sent_at` также обозначает закрытые устаревшие / использованные письма; это не подтверждение прочтения или попадания во входящие. При SMTP-отправке и аварии до фиксации транзакции возможен дубль; сообщение имеет стабильный Message-ID, но доставка строго один раз не гарантируется. Операторского экрана очереди и оповещений о сбоях пока нет.

Очередь и бизнес-изменения фиксируются в базе. Обработчик не выдаёт секреты через API или логи. Для одного серверного процесса работа встроена в API; отдельный воркер и распределённые лимиты — следующий эксплуатационный этап. SMTP-вызов имеет ограниченные таймауты, блокирует строку письма до результата.

## Уведомления

Уведомления внутри сайта: новая заявка организатору, принятие / отказ участнику, отмена активным заявителям и участникам, решение модератора по локации / GPX. Повторный идемпотентный запрос не создаёт повторное уведомление. Запись создаётся в той же транзакции, что решение. Текст общий: координаты, контакт сборов, email, GPX-оригинал и причина модератора не копируются. Ссылка не расширяет доступ к объекту.

Список, счётчик и отметка прочтения доступны только адресату; чужой ID возвращает 404. Пагинация по 20 элементов в интерфейсе, максимум 50 в API. Новые уведомления видны после обновления, без реального времени. Push и рассылки о покатушках не реализованы; SMTP обслуживает только доступ к аккаунту. Версия 0.7 добавляет уведомления о скрытии покатушки по жалобе и удалении связанного события при удалении аккаунта. Нет уведомлений о выходе участника и скрытии трека по жалобе. Для пилота определить эти сценарии, сроки хранения и настройки пользователя.
