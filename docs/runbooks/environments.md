# Окружения и данные

Локальная разработка: сайт на 5173, сервер на 3001, встроенная база в .data/postgres либо явный DATABASE_URL. По умолчанию сервер слушает только loopback.

Проверки: одноразовая база PGlite в системной временной папке; тест создаёт синтетические аккаунты, проверяет сохранение при повторном открытии и удаляет свою папку. Для TEST_DATABASE_URL использовать только пустую одноразовую базу; тест не должен запускаться на данных пользователей. GitHub CI проверяет встроенный и обычный PostgreSQL отдельно.

Рабочее окружение пока не развёрнуто. Перед пилотом: выбрать сервер и хранилище, домен / HTTPS, почтовый провайдер, политики данных, модерацию, удаление / экспорт аккаунта, резервные копии, восстановление и мониторинг. Нужны реальные замеры, а не только тестовый запуск.

Промышленный режим требует NODE_ENV=production, DATABASE_URL, COOKIE_SECURE=true и WEB_ORIGIN с HTTPS, REQUIRE_VERIFIED_EMAIL=true и настроенный MAIL_MODE=smtp. Перед reverse proxy определить доверенные прокси и лимиты по IP. Параметр HOST=0.0.0.0 допускается только в подготовленной среде; он расширяет сетевую доступность сервера.

Для локальной копии встроенной базы сначала остановить сервер, затем скопировать всю .data/postgres в закрытое хранилище. Это не утверждённый процесс промышленного резервирования. PostgreSQL: настроить штатное резервирование и проверить восстановление на отдельном сервере до пилота.

Текущие ограничения: нет общего распределённого limiter, не настроены домен / облако / S3 / PostGIS. Почтовая очередь и `.data/mail` содержат приватные ссылки доступа; не включать их в публичные архивы и логи. SMTP ещё не проверен с реальным провайдером. См. [инструкцию почты](pilot.md).

Старый Sites-проект не подключён к этой базе и продолжает показывать концепцию.
