# Локации, треки и жалобы: внутреннее тестирование

Роли `member` и `moderator`. Первый зарегистрированный аккаунт не получает привилегии автоматически. Роль назначает оператор с доступом к серверу, точному нику и выбранной базе. В браузере нет функции повышения прав.

Для встроенной базы сначала остановить API. Из корня проекта:

```sh
pnpm moderator grant exact_handle
pnpm moderator revoke exact_handle
```

Команда использует корневой `.env` / `DATABASE_URL` либо `.data/postgres`, как сервер. Проверить окружение до запуска. Для PostgreSQL также предпочтительно выполнять в согласованное окно обслуживания. Изменение роли действует на следующем запросе; для обновления меню перезагрузить страницу. Это локальный административный инструмент, не законченная система управления персоналом и аудитом выдачи прав.

## Проверка места

1. Участник указывает название, ближайший населённый пункт, координаты, сложность, описание и условия доступа. Обязательно согласие на публикацию. Статус `pending`.
2. Автор видит предложение в «Моих предложениях». Другие участники и гости не видят его, включая прямой API-адрес. Модератор видит очередь.
3. Модератор проверяет точку, право публикации и возможность въезда, описывает основание и публикует либо отклоняет. Отметка «Опубликовано» означает проверку публикации, а не юридическую гарантию доступа или безопасности катания.
4. Причина сохраняется в журнале и доступна автору / модератору. Решение можно принять только из ожидаемого статуса; устаревшая очередь получает 409.

Переходы: `pending → published / rejected`, `published → hidden`. Из жалобы модератор может скрыть объект. Редактирование, повторная подача, снятие скрытия и апелляция пока не реализованы. Не публиковать реальные маршруты до проверки разрешений. В локальном QA допустимы только явно обозначенные синтетические точки.

## Жалобы

Зарегистрированный участник отправляет причину и описание проблемы для опубликованного места, GPX-трека, доступной публичной записи либо открытой покатушки. Одна открытая жалоба на объект от одного автора. Жалобы не дают доступа к закрытым записям или приватной точке сбора. Репортёр и его email не раскрываются в публичных ответах.

Для GPX действует такая же очередь решений с причиной и журналом. Оригинал доступен только автору; модератор проверяет очищенную геометрию. Скрытие трека блокирует публичный доступ к связанным покатушкам и сведениям о сборе для участников. Подробнее: [треки и покатушки](tracks-rides.md).

В очереди модератор выбирает «Закрыть без скрытия» или «Скрыть объект» и указывает причину. Статус жалобы, скрытие и журнал изменяются транзакционно. Повторное решение отклоняется. Если запись стала закрытой после жалобы, роль модератора не открывает её содержимое; устаревшую жалобу можно закрыть. Удалённый объект тоже не восстанавливается.

Скрытая запись исчезает из публичной ленты, прямых ссылок и комментариев для остальных. Автор видит её с `hidden=true`; редактирование не снимает скрытие. Новые комментарии запрещены даже автору. Остальные открытые жалобы на уже скрытый объект закрываются вручную после проверки.

## Перед пилотом

Скрытие покатушки убирает её из общего списка, блокирует заявки и доступ участников к точке сбора. Организатор сохраняет доступ к собственному событию. Организатор и активные заявители получают личное уведомление без координат. Причина сохраняется в журнале; отдельного экрана истории решений по покатушкам пока нет. Подробнее: [версия 0.7](../sprint-05.md).

Назначить людей и сроки обработки, определить правила и апелляции, добавить уведомления, журнал изменения ролей и инструмент безопасного восстановления. Определить хранение и удаление журналов / жалоб, доступ к персональным данным. Процесс ещё не готов для публичного запуска.
