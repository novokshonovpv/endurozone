# Как работаем вдвоём

Одна задача — одна короткая ветка — один PR. Друг проверяет сервер и будущие приложения; вы проверяете продукт, сайт и сценарий райдера. Изменения общего API просматривают оба.

1. В задаче указать проблему, результат, владельца, критерии приёмки и зависимость. Не брать одновременно две крупные задачи.
2. Создать ветку `feat/…` или `fix/…` от актуальной `main`.
3. Сначала изменить контракт в `packages/contracts`, затем сервер и сайт; экспортировать OpenAPI.
4. Пройти `pnpm check`, содержательные серверные проверки и сборку. Для текста и оформления достаточно просмотра.
5. Открыть PR и описать результат для пользователя, проверку и ограничения. Второй основатель проверяет сценарий.
6. После приёмки объединить PR. Не переносить локальную базу или `.env` в Git.

В репозитории есть шаблоны задач и PR, а также автоматические проверки. Доступ друга на запись, защита ветки и GitHub Projects пока не настроены. Друг может уже читать публичный репозиторий и запускать ветку локально; для общего управления нужны его личный GitHub-аккаунт и согласованные права.

Статусы общей доски: «Идеи» → «Готово к работе» → «В работе» → «Проверка» → «Готово». Документ с текущим спринтом остаётся источником очереди, пока доска не заведена.

Перед первым большим вложением заполните вопросы в `docs/founders.md`. Код готов к проверке, но согласие друга на технологии и подписанное соглашение не подразумеваются автоматически.
